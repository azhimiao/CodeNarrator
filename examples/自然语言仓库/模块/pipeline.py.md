本模块连接配置、筛选和报告过程。成功时返回结构化报告与文本；只对两类处理错误给出失败结果。

## 确定本次使用的配置

### 概览

没有提供配置时创建默认配置，否则直接使用传入对象。

### 完整过程

任务接收记录与可选配置。只有当可选配置是空值时才创建默认配置；其他值直接作为配置对象使用，即使它在布尔判断中为假。创建配置发生在错误捕获范围之外，所以默认配置创建的异常不会被后述失败结果转换。程序不要求传入对象一定属于配置类型，只要它提供所需字段即可。外部配置的最低得分字段名称是 minimum，数量上限字段名称是 limit。

### 进一步理解

配置创建时的值错误与处理记录时的类型错误处于不同阶段，因此不能笼统说此任务会捕获全部错误。

<a id="section-3"></a>

## 成功路径

### 概览

依次筛选、构建报告、生成文本，三步都成功才返回成功结果。

### 完整过程

在受保护的处理范围内，读取配置的最低得分与数量上限并筛选输入。接着用选中记录构建报告，再把报告转换为文本。最后返回一个结果对象，包含为真的成功标记、结构化报告和文本。输入没有达标记录时仍是成功，报告数量为零、标识列表为空。选中记录以外的输入不参与报告标识读取；达到上限后的输入不再被筛选。成功结果的成功标记名称是 ok，报告名称是 report，序列化文本名称是 text；报告内数量名为 count，标识列表名为 identifiers。例如，唯一输入记录的 id 是甲、score 是零点八，使用默认规则时结果成功，报告数量为一，标识列表仅含甲，另附该报告的 JSON 文本。

### 进一步理解

任务没有检查所有记录再排序取最高分，而是在输入顺序上提早停止。因此后一条格式错误记录可能因提前停止而完全不被读取。

<a id="section-4"></a>

## 失败路径与未捕获错误

### 概览

处理范围内的键错误和类型错误转成失败结果，其余错误继续传播。

### 完整过程

筛选、报告构建或文本编码期间出现键错误或类型错误时，停止后续步骤，返回成功标记为假的结果，并把异常的类型名称作为原因。失败结果不含报告和文本，不重试也不回滚输入迭代已经发生的行为。原因只给类型名称，不包含原错误消息。属性错误、值错误及其他类型异常不在捕获范围内，会继续抛给调用者；读取不具备所需字段的配置或不具备读取方法的记录可能导致属性错误。失败结果的成功标记名称仍为 ok，值为假；原因字段名为 reason，其中键错误写作 KeyError，类型错误写作 TypeError。

### 进一步理解

键错误通常来自缺少必须读取的标识，类型错误可能来自得分比较或报告编码。仅说明原因的类别有助于区分失败，但不能指明哪条记录有问题。
