## 从一行程序取出步骤和参数

### 概览

先用 Python 标准库的词法工具将整行文本分成符号，固定取第一个符号为输出变量名、第三个为步骤名。

### 完整过程

先用 Python 标准库的词法工具将整行文本分成符号，固定取第一个符号为输出变量名、第三个为步骤名。只请求部分解析时立即返回这两项。完整解析时取第五个到倒数第四个符号之间的内容，丢弃逗号与等号，然后每两个符号作为一个参数名和参数值，组成字典，奇数个剩余符号不会进入配对。这里没有按完整 Python 调用语法理解表达式；值通常必须是单个变量名或单个带引号字符串符号。重复参数会后写覆盖；复杂表达式、空行、不合预期的格式可能错配、索引失败或词法失败。它也没有验证等号、括号与参数是否齐全。

可以把一行最简单的计数文本按字符理解为：先写输出名称 N，接等号，写步骤名 COUNT，接左括号，再写参数名 box、等号、输入名 BOX，最后右括号。词法结果按顺序共有十项：输出名称、等号、步骤名、左括号、参数名、等号、输入名称、右括号、逻辑行结束 NEWLINE、输入结束 ENDMARKER。即使原文本末尾没有显式换行，词法工具也产生逻辑行结束标记。完整解析选取第五项直到第七项，两端都包括，等价于舍去前四项及最后三项；去等号后只剩 box 与 BOX，配成一个参数。它不去掉任意注释或多余逻辑行，所以不能把这套固定位置规则理解为通用的程序语法解析。

## 把中间答案组合成表达式结果

### 概览

步骤名为 EVAL，创建时打印注册提示。

### 完整过程

步骤名为 EVAL，创建时打印注册提示。解析时取得输出变量和 expr 参数，使用 Python 的动态求值把该参数解出为表达式文本，并断言步骤名匹配。执行时遍历当前全部状态，另建格式化用字典：字符串 yes 和 no 转成真和假；仅由十进制数字构成的字符串原样保留；其他字符串在两侧添加单引号；非字符串原样引用。这不是改写原状态。保存原表达式用于展示，若文本含 xor，就把所有这种子串替换成不等号，再用状态字典替换花括号中的变量，最后动态求值，写入输出变量并返回。纯数字答案例如文本二会在表达式替换后成为可求值的数值字符，而不是先显式转换类型。表达式可访问普通 Python 求值环境，不是受限的逻辑运算器；未转义字符串、缺变量和无效表达式都可能失败。检查展示先移除原表达式的花括号，显示原式、替换后的式子和结果。

### 进一步理解

各步骤不统一捕获异常或回滚。读取不存在的状态、错误参数、模型加载或推理失败都会向调度器传播；调度器也没有恢复逻辑。开启检查时，步骤一般返回结果和展示文本，否则只返回结果。状态先写入再制作展示，所以展示失败时本步的写入可能已经发生。

## 定位文字描述的目标并保存候选框

### 概览

步骤名 LOC。

### 完整过程

步骤名 LOC。构造默认得分阈值零点一、去重阈值零点五，自动选 CUDA 第一设备或 CPU，载入 google/owlvit-large-patch14 的处理器与模型，设为评估模式，并保存阈值。解析图像变量、用动态求值得到的 object 文字和输出变量。普通检测把目标名嵌入“一张目标的照片”这一英文提示，与图像一起编码成张量，搬到设备，在关闭梯度记录后前向推理。输出中非空的张量移回 CPU，其他值保持。以图像高度、宽度作为目标尺寸作后处理，使用得分阈值取出框和分数，再转为普通列表。无候选时返回空列表；否则按分数降序排列，再逐项只保留严格大于阈值的候选，把四个坐标截成整数，左上坐标只限制最低为零，右下坐标只限制最高为宽高减一，没有完整检查坐标顺序或另一端越界。随后交给本项目去重过程，最终只返回框，丢弃分数。

若目标文字恰好为 TOP、BOTTOM、LEFT 或 RIGHT，则不跑目标推理，而分别返回上半、下半、左半、右半的一个几何框，中线由宽高除二取整数。边界分别使用零、宽减一、高减一。执行无论是否开启检查，都会复制原图并画框：默认第一个红色，其他蓝色，线宽五。把框列表存入输出名，另把画框图存入输出名加 _IMAGE 的状态项。检查时才嵌入原图与三百像素画框图，显示目标文字。排序、阈值和去重导致第一个通常是最高分的保留候选；几何半图没有模型分数。

各步骤不统一捕获异常或回滚。读取不存在的状态、错误参数、模型加载或推理失败都会向调度器传播；调度器也没有恢复逻辑。开启检查时，步骤一般返回结果和展示文本，否则只返回结果。状态先写入再制作展示，所以展示失败时本步的写入可能已经发生。

### 完整过程

步骤名 CLASSIFY，自动选 CUDA 第一设备或 CPU，载入 CLIP 大模型与处理器并设为评估模式。解析图像、对象列表、类别列表三个状态名及输出名。对象列表为空时内部设一个含整图的局部列表却立即返回空列表，不进行推理。外层执行仍把这个空列表写到输出状态；普通模式返回空列表，检查模式将空列表整理为空的展示结果文字，再返回空列表与展示。否则按每个框裁图；若类别列表仅有一个元素，先追加 other 得到新的局部查询列表，不修改原类别列表。因此后面再次检查“类别数是否为一”的特殊分支，对普通列表已经无法到达；该分支本想仅取最高匹配对象、写 class 和未取整的百分比分数，但当前通常执行不到。

实际主路径将每类转成英文照片描述，图像和文字处理为张量搬到设备，关闭梯度后分别取特征、按二范数归一化并矩阵相乘。每个对象沿类别维选相似度最高的类别，直接在原对象字典上添加或覆盖 class 与 class_score；后者为相似度乘一百后保留一位小数。把对象按分数降序建立新列表，再保留有 class 的项，提取类别集合。对集合的每一类，从零作为最高分起点，只接受严格大于零的分数，保存最佳对象；若该类全为零或负分，则仍向结果加入专用空值 None，而不是空列表；输出例如可成为含一个 None 的列表。集合遍历使最终类别输出顺序没有固定保证。每类只输出一个对象，多个同类目标会被压成一个，other 也没有专门排除。写入状态的结果仍引用原对象，所以附加分类会影响原对象列表内共享项。检查时把结果中各对象的框、标签、分数整理成展示文字，若含空值会失败。

### 进一步理解

各步骤不统一捕获异常或回滚。读取不存在的状态、错误参数、模型加载或推理失败都会向调度器传播；调度器也没有恢复逻辑。开启检查时，步骤一般返回结果和展示文本，否则只返回结果。状态先写入再制作展示，所以展示失败时本步的写入可能已经发生。

## 用文字引导修补第一个选中对象

### 概览

步骤名 REPLACE。

### 完整过程

步骤名 REPLACE。创建时固定使用 CUDA，没有 CPU 回退；载入 runwayml/stable-diffusion-inpainting 的 fp16 修订，以 PyTorch 半精度存储，再搬到 CUDA，并把内置检查器替换为直接放行过程。解析图像、对象状态名，用动态求值取得 prompt 字符串和输出名。制作掩膜只取对象列表第一项，直接取得其 mask 数组引用，先把严格大于零点五的位置原地改成二百五十五，再把当前不大于零点五的位置改成零，最后转八位数组成为图像；因此原对象的掩膜本身已被改写。空对象列表会索引失败。

缩放填充过程新建默认五百一十二见方、与输入同模式的底图，复制输入后按比例缩略，不放大超过限制，贴到左上零点，返回填充图及缩略后宽高。预测分别对掩膜和原图填充，调用修补管线：提示文字、填充原图和掩膜，引导尺度七点五，五十次推理步，不显式设随机种子。取第一张输出，以原图缩略宽减一、高减一为右下端裁掉填充，再缩放回原始尺寸；减一意味着相较常见的右下排他裁图会少保留末边像素。保存新图并按需展示。展示的红色步骤标题误用了输入图变量名，没有使用 REPLACE。

另有合并图像的辅助方法未被当前执行路径调用：它打印尺寸，用旧 NumPy 的 np.float 别名把掩膜转浮点并除二百五十五，再扩三通道，以掩膜混新图、补掩膜混旧图，转八位返回。若所装 NumPy 已无该别名，此辅助方法会失败。不要把它说成实际修补后还会自动执行的混合步骤。
