# 项目用途、演示入口与扩展方式

说明文档介绍 VisProg：借语言模型把自然语言视觉任务转成程序，逐行调用现有视觉模型、图像算法或普通计算，再给出结果与可视化过程。列出组合问答、双图判断、图像编辑、外部知识标注四个 Notebook；建议先依环境清单创建环境，再在入口填写 OpenAI 凭据。四类入口大致都准备路径、设置密钥、导入核心与提示、创建对象、读图、设置问题、生成程序、执行并显示。README 示例对 camel1 图分别定位人和动物，各自计数后相加，最后读取总数；它是示范程序，不保证对任意图片准确。

文档将失败分成提示分布不适合和当前工具能力不足，建议前者补充可行示例，后者新增步骤类型并在注册表登记，再新增提示和任务入口。COUNT 的示范说明解析参数、执行写状态、按需生成 HTML 的共同接口。文档还说可尝试以函数签名和说明替代少量示例，这是一种可扩展方案，当前默认文件没有实现自动切换。

文档提到视觉问答已从 ViLT 改为 BLIP，程序生成升级 text-davinci-003；实际 LIST 步骤仍用 text-davinci-002，所以不能把升级描述套到所有补全调用。图片用来展示能力、模块和推理过程，不包含额外可执行逻辑。末尾给研究引用信息。开头推荐后续 CodeNav 工作，描述其迭代搜索、自由代码执行和错误修复能力；这些属于另一项目的介绍，不能当成当前 VisProg 已有能力。README 的端到端运行描述也不是本次实际验证结果，当前固定版本仍依赖旧接口、设备与模型资源。
