# 架构与状态

初始状态是由入口创建的字典，图像存于 IMAGE 或 LEFT、RIGHT。Program 和每行小程序都引用它，解释器对它逐步增加文字答案、计数、框、对象和图像；失败不恢复旧值。普通定位的框伴随 _IMAGE 展示图，Loc2 却只存带 box、category 的对象。分割与人脸对象还含 mask 和实例编号。选择后的列表复用原对象，分类添加 class 与 class_score 会反映到源列表；修补阈值化 mask 会改写源数组。RESULT 只读指定项，不建立左侧输出名。最终返回最后一行结果和整个状态。表达式的格式化字典是另建的，但不构成执行隔离。图像框坐标有闭区间计算与 Pillow 排他裁剪的混用，具体边界见各过程。

## 组件关系

四类任务入口 → 任务提示：问答入口固定 all；编辑和标注入口插入指令，标注默认上限二十。

四类任务入口 → 程序与执行核心：创建生成器与任务解释器，传入同一初始状态并开启检查执行。

程序与执行核心 → 任务登记和实际步骤：任务名先决定登记表，行中的步骤名再查表调用；未知任务无最终错误分支，未知步骤引发键错误。

任务登记和实际步骤 → 框去重：普通对象检测按阈值筛候选后用交并比去重；Loc2 调低两项阈值。

任务登记和实际步骤 → 展示工具：制作检查图文；部分图片即使关闭检查仍会制作，展示失败可能在写状态后发生。

## 双图判断的一次完整任务

1. 入口选择任务、准备图像状态和提示参数。

失败边界：路径、凭据、导入或注册模型失败时中止。

2. 生成整段程序，再以共享状态按行执行。具体路径：两图入口先使仓库可导入、设置环境凭据，创建 nlvr 的三类步骤，固定使用全部十二条示例的提示。将两张骆驼图片缩略并转 RGB，放入共享状态。陈述被填到提示末尾，补全服务一次生成完整程序；概率指标被入口丢弃。执行器逐行解析步骤名并动态分派，问答写文字答案，表达式把 yes/no、数字与逻辑组合成结果，结果步骤只读状态。入口最后显示最终值和检查展示。任一加载、网络、格式、缺变量或展示失败都会中止，已写入的初始状态不会回滚。

失败边界：没有自动程序修复或回滚，异常中止后续步骤。

3. 登记步骤读取并写入共享状态，按需产生检查展示。

失败边界：格式、缺字段、推理或展示失败向外传播。

## 按指令编辑图像

1. 入口选择任务、准备图像状态和提示参数。

失败边界：没有自动程序修复或回滚，异常中止后续步骤。

## 图文模型与预训练加载的使用契约

版本依据：Transformers 四点二十七点二，权重标识见各步骤。

处理器准备图像和文字张量；预训练载入可能联网；项目按余弦分数选择，不是正确概率。

下载、设备、内存与推理失败没有自动恢复。

## 图像修补的使用契约

版本依据：Diffusers 零点十四点零与 fp16 模型修订。

白色掩膜对应重绘区域，使用五十步、引导尺度七点五；项目先缩放填充，未固定随机种子。

固定 CUDA 无 CPU 回退，空对象、尺寸与模型失败传播。

## 远端补全的使用契约

版本依据：仓库锁 OpenAI 零点二十三点零客户端，属于旧接口调用。

生成器和列表步骤一次请求第一条补全，不验证或自动修错。

不能保证现时远端模型可用，网络和接口失败传播。
