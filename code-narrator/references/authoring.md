# 翻译包格式与写作规范

工具只负责确定性机制。空包是构建中的待办，不能直接作为最终产物。

## 文件包

扫描后，manifest.json 中每个 supported 文件对应 translations 下的一份 JSON。文件名由路径哈希生成，通过清单或 context 命令查找；不要手写虚构单元 ID。

字段如下：

| 字段 | 内容 |
|---|---|
| schema_version | 整数 1 |
| source_file、source_sha256 | 保留扫描得到的相对路径与当前内容哈希 |
| title | 表达职责的自然语言标题 |
| overview | 该文件的实际职责、上下文和组成 |
| sections | 按逻辑组织的完整处理过程 |
| review | status 为 reviewed，method 如实说明谁用什么方式检查过 |

每个 section 包括：

- title：自然语言标题。
- unit_ids：由本段正文承接的真实单元 ID 列表，只能属于当前文件。
- summary：简洁且准确的行为概览。
- body：完整处理过程。包含必要的输入、条件、步骤、计算、输出、异常、副作用和上下文；以完整自然语言表达。
- details：为不熟悉概念的读者提供进一步说明，可为空字符串。
- evidence：支持本段说法的单元 ID，可跨文件，但必须真实存在。
- links：可为空列表。每项为 target（单元 ID）和 label（自然语言关联名称）。渲染器自动链接到目标正文。

一个章节可以承接多个语句，但应确实解释所有相关行为。模块单元可以由介绍初始化或文件整体组成的章节承接。不能只写函数摘要再把全部语句 ID 放进去凑覆盖。

对配置和项目文档，脚本提供 Document 单元：仍需阅读内容，翻译它如何定义、约束或描述项目。配置含义应连接到实际读取与行为，文档声明与实际实现有出入时应指出。没有对应行为的元数据如实说明，不编造功能。

Notebook 有 Notebook 容器、逐格 NotebookCell 及代码结构单元，unit.cell 为从零开始的保存单元格编号，行号相对该格。每格正文要接上前后状态；空格解释没有新行为，Markdown/raw 格解释其内容与作用。历史输出和执行计数不是新的可执行步骤。跨格状态、特殊命令与执行顺序的要求见 semantic-model.md。

## 项目包

project.json 包含：

| 字段 | 内容 |
|---|---|
| schema_version、snapshot | 整数 1 与当前 manifest.snapshot |
| title、overview | 项目自然语言名称与整体行为 |
| architecture | 模块组成和关系；完整自然语言 |
| reading_order | 推荐顺序中的源文件相对路径，渲染器转为正文链接 |
| flows | 至少一条流程；每项包含 title、body、unit_ids（支撑流程的真实 ID） |
| data | 关键数据结构、流向与生命周期 |
| dependencies | 本项目用到的外部能力、相关版本与行为边界；没有第三方依赖则如实说明 |
| glossary | 当前阅读者需要的概念解释 |
| unknowns | 列表；每项含 description 和布尔值 blocking |

unknowns 为空列表表示未记录未解决问题，不是正确性证明。已知的开放配置、网络结果等可以在正文完整表达，无需伪装成分析未知。尚未查明且妨碍核心理解的问题必须 blocking=true，render 将拒绝交付。

## 事实与表达

自然语言中保留精确条件、常量和单位；不要求读者会解析源语言语法。比如“恰好等于最低得分时也保留”，比“按条件筛选”更准确。说清返回新集合是否同时复制其中对象、异常在哪里捕获、失败后哪些步骤不再执行。

文件标题不用原函数名解释原函数名。库名称可以出现，但必须给出当前行为的自然语言说明。原配置、源码片段、中文赋值伪代码与大量未解释标识符均不应进入阅读正文。

正文不使用外部链接补全实现；关联关系优先用 links 字段，流程用 unit_ids 建立自然语言跳转。若手写内部 Markdown 链接，使用渲染后的真实相对路径，空格进行 URL 编码，锚点使用生成器的 section-N。

三层内容同时保存在成品中：概览用于定位，完整过程承接实现，进一步理解提供概念和例子。student 多解释框架与中间状态，developer 减少常识重复，domain 用领域语境说明实现，但任何背景不能省略关键事实。

## 更新和复核

重新扫描后旧包不会自动匹配新哈希。先核查实现变化与跨文件影响，再更新字段。项目快照也需在复核之后更新。证据和映射只证明可追溯，不能证明解释正确；review 是可审计的复核声明，不是工具做出的正确性判断。
