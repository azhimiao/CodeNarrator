项目测试执行方式为 Python 标准库的 unittest 测试发现。15 个测试通过，覆盖：

| 范围 | 实际验证 |
|---|---|
| 完整构建 | 62 个结构均有正文映射，成功生成成品 |
| 独立分发 | 删除临时源码和构建目录后，成品内部链接仍有效 |
| 缺项拦截 | 删除一项结构对应后，验证与生成被拒绝 |
| 更新检查 | 新增、修改和删除文件都被识别 |

## 自编示例

独立 Agent 只获准读取自然语言目录，回答了七组问题：阈值相等、顺序与提前停止、缺少不同字段、对象共享、上限一点五、错误捕获边界、序列化顺序与外部操作。

该检查指出“空值”定义和对外字段名称不够明确。已补充专用空值与空字符串的区别、输入输出字段的自然语言说明及完整输入情境。其余回答与源码和行为测试一致。此项是 Agent 独立阅读检查，不是人类用户实验。

## Skill 从零独立试用

另一位 Agent 只获得 Skill 与使用请求，自建两份 Python 文件和一份 JSON 配置，按 Skill 实际完成扫描、上下文读取、翻译包编写、验证与生成。共 3 个文件、92 个结构，生成 13 份自然语言文件；日志保存在工作区的 .forward-test/logs，成品位于 .forward-test/natural-language。

空白翻译未通过验证，也不能生成成品。已完成正文通过验证与生成，更新检查没有误报。额外检查确认旧快照、覆盖已有目录及将成品写进源码的操作受到拦截。

该试用发现带井号文件名导致链接编码错误，以及复核方式误填列表时验证器漏报。已在主工具修复，并增加实际渲染特殊文件名和拒绝错误字段类型的回归测试。此项是独立 Agent 前向试用，不是人类用户研究。

## 能力边界

- 语义由宿主 Agent 生成；脚本不声称自行理解任意程序，也不接入另一套模型 API。
- 结构覆盖和文本配置的文件级承接不能证明每句解释准确，仍需语义复核。
- 跨文件更新先由全局快照阻止旧译本交付，再由 Agent 复核相关正文；当前不是精确自动重算全部调用影响的分析器。
- 不支持的语言或 Notebook 必须补充支持或明确缩小范围，不能悄悄跳过核心流程。
- 只有小型项目验证，尚未开展人类参与者实验或大型科研仓库评估。
- 正文目前用 Markdown 分层章节承载，无需源码阅读器；没有实现双向自然语言编辑、在线协作或交互式问答服务。
