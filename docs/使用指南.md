# CodeNarrator 使用指南

CodeNarrator 是交给编程 Agent 使用的 Skill。Agent 负责理解与翻译；Python 标准库工具负责可复核的构建流程。完整目标与真实译本见 [项目首页](../README.md)。

## 安装

需要 Python 3.10+：

```bash
python scripts/install_skill.py
python scripts/install_skill.py --update
```

第一条命令安装新 Skill；第二条显式更新已有 Skill 并保存旧版 ZIP。默认目录为 `CODEX_HOME/skills`，没有配置时为 `~/.codex/skills`。用 `--skills-dir` 指定其他技能目录。也可以从 [Releases](https://github.com/azhimiao/CodeNarrator/releases/latest) 下载 ZIP，解压后把整个 `code-narrator` 目录放入技能目录。

向支持 Skill 的 Agent 指定 `$code-narrator`、输入仓库、读者背景、独立构建目录和新的成品目录。其他 Agent 可以直接读取 [SKILL.md](../code-narrator/SKILL.md)。Skill 通过 Agent 本身完成理解与写作，无需手动填写 JSON 或另设模型 API。

## Agent 使用的命令

以下路径是占位示例；替换为本机路径。输入、构建和成品目录应相互独立。

```bash
python code-narrator/scripts/narrator.py scan /path/to/source --work /path/to/work --profile student
python code-narrator/scripts/narrator.py pending --work /path/to/work
python code-narrator/scripts/narrator.py architecture --work /path/to/work
python code-narrator/scripts/narrator.py chunks --work /path/to/work
python code-narrator/scripts/narrator.py context --work /path/to/work --file engine/utils.py
python code-narrator/scripts/narrator.py review --work /path/to/work
python code-narrator/scripts/narrator.py validate --work /path/to/work
python code-narrator/scripts/narrator.py render --work /path/to/work --out /path/to/new-product
python code-narrator/scripts/narrator.py freshness --work /path/to/work
```

`scan` 生成待办与索引。`architecture` 提供保守的导入候选、反向引用与邻居符号；Agent 继续追踪动态分派、状态与业务关系。`chunks` 将长文件分成最长 160 行的片段并保留所在定义；`context` 可加 `--chunk <编号>`。Notebook 保留逐格来源、保存顺序与特殊命令，工具不会执行单元格，也不会把保存的输出当作已验证结果。

Agent 编写文件译文、项目总览和 `model.json`，记录组件、关系、状态、依赖契约、执行路线，以及正常、边界与失败问题。`review` 提供当前指纹供复核；它本身不表示批准。正文变更使旧复核失效。

`validate` 检查范围、结构对应、快照、依据、归属、引用与复核一致性。`render` 在检查通过后生成独立成品，核查内链并拒绝覆盖已有目录。工具检查不能证明语义一定正确；实际行为核查与只读译文的独立验收仍是工作流程的一部分。

## 阅读背景与维护

`student`、`developer`、`domain` 三种背景由 Agent 用来调整基础说明和领域解释深度，每种都保留实现事实。正文提供概览、完整过程与进一步理解三个层次。

保留构建目录即可续作。输入变化后重新 `scan`，旧译文保留；新增、修改、删除及导入反向影响列为待办。Agent 复核受影响的正文、动态关系与状态，再生成新成品。二进制素材、缓存、凭据与不支持项明确登记；核心模块不应为了通过检查而被排除。

当前深度支持 Python 与 nbformat 4 的 Python Notebook。其他语言及非 Python 内核尚不在 V1 支持范围。

## 复现验证

准备两个固定版本的真实输入，见 [sampleproject 来源](../examples/REAL_PROJECT.md) 和 [VisProg 来源](../examples/VISPROG.md)，再运行：

```bash
python examples/build_demo.py
python examples/build_real_demo.py
python examples/build_visprog.py
python -m unittest discover -s tests -v
python scripts/package_release.py
```

样例 build 脚本保存的是固定提交已经编写的译文资料，用于复现成品。面对新仓库时，Agent 必须重新理解并编写译文。

VisProg 契约测试隔离运行相关定义，不导入整套视觉环境、不下载权重、不调用补全服务。未准备 VisProg 时，对应测试会明确跳过。发布验收记录要求全部输入到位、41 项通过、零跳过。详细证据见 [V1 验收记录](V1验收记录.md)。
